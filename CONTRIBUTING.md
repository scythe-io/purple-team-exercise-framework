# Contributing to the Purple Team Exercise Framework

Thank you for your interest in contributing to the Purple Team Exercise Framework (PTEF). This framework has become the industry standard through the collective efforts of security professionals worldwide.

## How to Contribute

### Reporting Issues

If you find errors, outdated information, or have suggestions for improvement:

1. Check existing [issues](https://github.com/scythe-io/purple-team-exercise-framework/issues) to avoid duplicates
2. Open a new issue with a clear, descriptive title
3. Provide as much context as possible:
   - Which document/section contains the issue
   - What the current content says
   - What you believe it should say
   - Any references or sources supporting your suggestion

### Submitting Pull Requests

We welcome pull requests for:

- **Spelling/grammar corrections**
- **Broken link fixes**
- **Clarifications** to existing content
- **New templates** for purple team exercises
- **Case studies** or practical examples
- **Updates** to reflect current industry practices
- **Translations** (in separate directories)

#### Pull Request Process

1. **Fork** the repository
2. **Create a branch** for your changes (`git checkout -b fix/typo-in-planning-section`)
3. **Make your changes** following the style guidelines below
4. **Test** any links you add or modify
5. **Commit** with a clear message describing the change
6. **Submit** a pull request with:
   - A clear title summarizing the change
   - Description of what was changed and why
   - Reference to any related issues

### Style Guidelines

#### Documentation

- Use clear, professional language
- Write in active voice where possible
- Define acronyms on first use
- Use proper MITRE ATT&CK formatting (e.g., T1059.001)
- Include references for claims about adversary behavior

#### Formatting

- Use Markdown formatting consistently
- Maintain existing heading hierarchy
- Use tables for structured data
- Include alt text for images
- Keep line lengths reasonable for readability

#### Templates

When contributing templates:

- Include clear instructions for use
- Provide example entries where helpful
- Ensure compatibility with common tools (Excel, Word, etc.)
- Follow existing naming conventions

### What We're Looking For

High-value contributions include:

- Real-world lessons learned from purple team exercises
- Templates that have proven useful in practice
- Improvements to the Purple Team Maturity Model
- Integration guidance with other frameworks (MITRE ATT&CK, etc.)
- Detection engineering examples
- Metrics and measurement approaches

### What We Generally Don't Accept

- Vendor-specific tool promotion (keep content tool-agnostic where possible)
- Content that hasn't been validated through real exercises
- Major structural changes without prior discussion in an issue
- Content that contradicts established security best practices

## Code of Conduct

- Be respectful and constructive in all interactions
- Focus on improving the framework for the community
- Give credit where credit is due
- Respect the intellectual property of others

## Questions?

If you have questions about contributing, feel free to:

- Open a discussion in the repository
- Reach out to the maintainers through the issue tracker

## Recognition

All contributors are recognized in the [Contributors section](./PTEFv4.md#contributors) of the framework. We value and appreciate every contribution that helps improve purple teaming practices worldwide.

Thank you for helping make the Purple Team Exercise Framework better for everyone!
